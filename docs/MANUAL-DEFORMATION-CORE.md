# Shared manual deformation core, capabilities v2

`app/src/main/assets/manual-tools.js` implements user-directed manual brushes only. It does not detect faces, infer identity, load a model, make network calls, or claim SOTA quality. The core remains one UMD implementation for browser and CommonJS use. No dependency, signing, desktop source, editor or project-format changes are introduced by this core extension.

## Compatibility and feature detection

The existing `push` and `restore` operations retain their calculation order, kernel, resampling, limits, alpha handling and final source sampling. The exact pre-extension source is preserved at `tests/fixtures/manual-tools-legacy-v29.cjs`:

- Legacy SHA-256: `d28e4cef2a7f589a667e89b691bad72d31f0907d40ed47fe897f564d3dd12762`.
- Current core SHA-256: `37617b5654e7479a2cc2b96ce047845a44cbc725a3f8f618069513d4f051a779`.
- The core test compares the complete returned pixels and diagnostics against that frozen implementation on 48 deterministic random fixtures. The 20 original manual-tool tests remain unchanged and pass.

`CAPABILITIES` is a frozen object with `version: 2` and a frozen `kinds` array containing `push`, `restore`, `bloat`, `pucker`, `twist-cw`, `twist-ccw`. Clients should fail closed for missing/incompatible capabilities rather than pass new commands into a legacy engine. The capabilities version is not a new project or selection recipe version.

Every command retains exactly these six own data fields:

```js
{
  kind: 'bloat',
  sourceRevision: 'the-current-immutable-source-revision',
  radius: 0.2,
  strength: 0.6,
  points: [{ x: 0.5, y: 0.5 }],
  selection: null
}
```

Radius is within `[0.002, 0.5]`, strength within `[0, 1]`, and normalized coordinates within `[0, 1]`. All numbers must be finite. Unknown/missing fields, sparse/accessor arrays, accessor fields, unsupported kinds, mismatched revisions and excessive command/snapshot counts reject. Validation deep-copies command points and selection snapshots. The source revision is an application-supplied binding, not a content hash generated by this core.

## Coordinates and deterministic brush dose

Normalized points refer to pixel centers: `xPx = x * (width - 1)` and `yPx = y * (height - 1)`. Radius is `radius * min(width, height)`. Screen y increases downward.

For the four new modes only:

1. Remove duplicate vertices and redundant forward-collinear vertices. The relative cross-product tolerance is `1e-12`, only to absorb floating-point subdivision roundoff. Corners and reversals remain.
2. Compute the entire polyline arc length `L` in pixels, not a new sampling grid per pointer event.
3. Let spacing `d = radiusPx * 0.35`. For positive `L`, `intervals = max(1, ceil(L/d - 1e-10))`; otherwise intervals are zero.
4. Use `intervals + 1` uniformly spaced samples including both endpoints. A stationary path has exactly one sample, regardless of how often a held pointer reports the same coordinate.
5. Each sample has dose `(1 + L/d) / (intervals + 1)`. Thus total dose is one tap plus distance-proportional sweep dose. Tiny endpoint jitter tends continuously to one tap instead of doubling the effect. Zero strength produces no samples.

Sparse and dense collinear samples, subdivided corner paths and repeated stationary samples replay byte-identically in tests. Distinct commands are intentional distinct brush strokes and therefore can accumulate. Historical push/restore sampling is unchanged.

## Common field and direction

Every mode updates the existing inverse displacement fields `dx`, `dy`. The image is sampled once, at the end, from immutable source RGBA. It is never repeatedly resampled per dab.

Let `q` be the destination's vector from a sample center, `K` the existing compact C1 radial kernel, `S` the destination selection weight, `a` strength, and `D` sample dose. `K` is one through half-radius, smoothly fades to zero at the outer radius, and is zero outside.

- Bloat proposes inverse increment `-0.18 * a * q * K * S * D`. Looking up source locations closer to the center makes image features expand outward.
- Pucker proposes `+0.18 * a * q * K * S * D`, visibly shrinking features inward.
- Twist proposes `(R(theta) * q - q) * K * S * D`, where `theta = -0.28*a` for visible clockwise and `+0.28*a` for visible counterclockwise. Trigonometry is computed once per command. A marker initially east of the brush center moves down for clockwise and up for counterclockwise in screen coordinates.

Selection attenuates the vector outside the rotation, rather than changing the angle and silently changing feather semantics. Kernel and dose also attenuate the proposed vector. The common limiter can reduce these proposals, especially near hard selection edges or after accumulated strong strokes. This is intentional, not an unconstrained warp.

## Selection and alpha boundaries

Selection protects zero-weight **destination** pixels. It does not isolate source/donor pixels: a selected destination can sample an unselected source neighbor through the inverse map and bilinear interpolation. Do not describe the feature as source isolation or as a segmentation guarantee.

The low-level core preserves the legacy alpha policy for compatibility: destination alpha is unchanged, fully transparent destination RGBA remains byte-identical, and source color interpolation is alpha-premultiplied. The mobile integration must continue rejecting translucent source input before entering this manual tool. This core is not an exception to that mobile gate.

A full-strength restore whose flat kernel plateau covers all displacement returns exact source bytes by setting displacement to zero. It is not a second warp that tries to undo an already resampled bitmap.

## Shared no-fold and domain guarantee

All six modes pass their proposals through the existing algorithm:

1. Clamp each proposed source coordinate to the closed source rectangle before calculating a common step scale.
2. Inspect horizontal and vertical displacement differences in the affected rectangle plus a one-pixel halo.
3. Solve the existing quadratic edge-scale constraint so the final displacement edge norm stays at or below target `0.44`, with Float32 rounding margin and the existing final rejection threshold `< 0.45`.
4. Apply one common scale to both displacement components and all affected destinations.

The interpolated displacement derivative has each column bounded by the maximum edge norm `g`. Therefore its operator norm is at most `sqrt(2)*g < 1`; `I + derivative(displacement)` stays nonsingular with positive determinant. The reported determinant lower bound is `(1 - sqrt(2)*g)^2`. Domain clamping followed by common scaling keeps each updated source position in the source rectangle by convexity. No new mode bypasses this proof or supplies a separately interpolated field.

Cooperative cancellation checks occur before field allocation and during selection, weight, limiter and sample loops. Cancellation throws `AbortError` / `MANUAL_CANCELLED` without mutating source RGBA. It is a synchronous callback mechanism; callers must provide a cancellation signal appropriate to their execution environment.

## Allocation-free export preflight

```js
const metadata = MintManualTools.planLiquify(width, height, commands, {
  sourceRevision: currentRevision
});
```

The returned frozen object contains exactly `width`, `height`, `pixels`, `workUnits`, `maxWorkingBytes`, `totalSteps`. It reuses the same strict validation and private planner used by `liquify`. It constructs bounded command/path metadata, but no RGBA buffer, displacement field, mask, scratch field or other typed pixel array. Tests replace every typed-array constructor with a throwing sentinel and still preflight a 4096-by-4096 image successfully.

Preflight and render enforce the same limits: edge 16,384, pixels 16,777,216, commands 128, command points 4,096, snapshot commands 1,024, snapshot points 16,384, steps 8,192, work 800,000,000 units and core estimated memory 536,870,912 bytes. Oversized geometry or cumulative workload must fail before a caller allocates full-resolution export pixel buffers. Work units are a conservative implementation budget, not milliseconds or a device benchmark. New-mode expanded brush boxes cost 110 units per pixel per step, while legacy estimates stay unchanged.

`maxWorkingBytes` is the existing core working-set estimate, not the entire application's peak memory. It includes caller-owned input RGBA, output RGBA, two Float32 displacement fields, Float32 weights, optional selection and feather fields, a Float64 blur prefix and a 2 MiB metadata allowance. Canvas/GPU buffers, compressed source bytes, other editor stages, runtime overhead and duplicate export buffers are additional caller costs.

Representative metadata for one bloat tap, radius `0.1`, strength `0.6`, without selection:

| Dimensions | Pixels | Work units | Estimated core bytes | Steps |
|---|---:|---:|---:|---:|
| 1080 × 1080 | 1,166,400 | 21,557,240 | 25,433,800 | 1 |
| 2048 × 1536 | 3,145,728 | 54,611,192 | 65,028,104 | 1 |
| 4096 × 4096 | 16,777,216 | 309,206,264 | 337,674,248 | 1 |

These accepted plans do not mean every permitted image/brush combination fits: a half-image-radius twist at 4096 square or a sufficiently long/multi-command sweep is rejected by the cumulative work limit. Export callers should report that restriction, not silently drop deformation or downsample an explicitly original-resolution export.
