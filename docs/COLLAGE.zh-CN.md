# 本地 2–4 格拼图（源码检查点）

## 真正执行的功能

打开一张主照片并完成已有编辑后选择「拼图」。界面会明确说明「当前作品作为第一格」。这不是更换主原图，也不新建覆盖项目：点击「应用」后只新增一条有序、可撤销的拼图步骤。

- 2、3、4 格；横排、竖排或网格。3格网格为左侧大格、右侧上下两格。
- 每格可选择「填满」或「完整适应」。填满可以用水平/垂直焦点滑杆或数值调整裁切，完整适应保留整图并居中。
- 画布宽高、外边/格间间距、背景颜色和透明度可修改。此版本用数值焦点调整裁切，不声称支持格内拖拽裁切。
- 第一格固定为当前已处理作品。其它格由用户通过本地文件选择器导入或替换，不读取网址、外部素材库或任意文件路径。
- 附加导入有可点击的「取消导入」，不使用遮住取消按钮的全屏忙碌层。导入中不能打开导出窗口或保存。取消、切换工具、失焦或主图替换会使旧回调失效。
- 减少格数暂存本次工具会话中隐藏格的设置和素材；再次增多可恢复。只提交当前显示的格子。退出未应用工具前保留已有的丢弃确认。
- 点击格子只选中它，不修改图片。第二指、取消手势或失焦不提交临时选择。
- 应用后可撤销/重做整个步骤、通过历史回退。此版本没有任意已提交拼图的逐格重编，不应称作可编辑多画板工程。

## 尺寸、来源和透明度

声明输出每边为 256–4096 像素，总计不超过 800 万像素。交互预览最长边 900，**预览缩小不会改写声明宽高**。完整导出仍按原图/工作副本来源依次重放历史，直到拼图产生声明的画布尺寸；后续裁剪、旋转、文字、手动步骤仍按其当前图像坐标执行。最后的导出长边缩小设置继续在末尾执行。

第一格在「原图尺寸」导出时从保留的主原文件重放，在「工作尺寸」导出时从明确的最长边2560工作副本重放。同一声明拼图尺寸不代表两种来源细节相同。大原图和所有中间步骤先受现有预算约束，声明较小的拼图或末尾缩小不能绕过这些检查。

附加图片只接受静态 PNG/JPEG/WebP，原输入最多12MiB、800万像素、最长边4096。每张变为最多1024长边、1,048,576像素的RGBA8副本嵌入本地草稿；不保留其原文件、文件名、路径或附加EXIF。放大格子不会增加照片细节。应用前会列出各副本尺寸和两种导出方式是否可用。

- 所有历史中的图片贴图和拼图附加素材共享最多4张、16MiB解码RGBA预算，重做历史也计入。
- 拼图运算额外缓冲估计限制128MiB，累计工作估计128,000,000单位。估计不是实际进程峰值内存承诺；字符串、主图、浏览器和原生解码器另有开销。
- PNG保留合成后的透明度；JPEG按既有流程在最终缩放后合成白底。Canvas与图片解码器可能规范化完全透明像素隐藏RGB，不宣称隐藏RGB逐字节保存；主原文件字节仍保留。
- 导出重新编码当前结果，不复制原照片的EXIF或嵌入原始缩略图。草稿仍保留原图和可逆历史，不应将草稿当作已脱敏的导出成品分享。

## 本轮验证及未验证

纯布局/校验、实际生产操作和受控DOM交互新增51项通过；生产编辑器的真实Native Canvas PNG/JPEG新增8项通过。独立审核还核对完整4000×1000高频主源与2560工作副本得到不同、各自正确的导出，不借用900预览冒充原尺寸。

自制几何图的2/3/4格实际PNG、原文件保留和撤销/重做证据在 `quality/collage-evidence/`。不是手机截图。独立审核发现的“导入中能打开导出模态框并遮住取消”已在入口增加拒绝，保存入口原先已拒绝。

真实WebView布局、系统文件选择器生命周期、实体手机手势、峰值内存与响应时间仍未运行；没有新增签名密钥或可安装APK。这是本地传统布局/合成工具，不是学习型算法、SOTA或专业模板平台。

复现：

- `sh tests/run-pure.sh`
- `node --test tests/native-canvas/collage-pixels.test.cjs`（需已安装的 `@napi-rs/canvas`）
- `node tools/render-collage-evidence.cjs`
