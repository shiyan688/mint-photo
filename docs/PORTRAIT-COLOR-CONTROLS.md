# 可逆自然人像控制 · 2026-10-22 云端源码检查点

## 不是最终 SOTA 重做版

本次完成的是可直接产生像素结果的经典局部控制、原文件重放与质量回归，不是学习型皮肤精修、参考妆容迁移或醒图等效产品。MediaPipe 仅提供本地人脸关键点，不能把成功检测到脸说成美颜模型通过。BiRefNet/SegFace 不在本 Android APK 中；旧低分辨率 Selfie Segmenter 仍不是精细发丝抠图。

“亚洲人风格”在这里体现为用户可选的自然通透、柔和妆感方向，不通过脸推断族裔、性别或身份，不统一美白或自动改变眼鼻轮廓。所有控制默认零；原图与原始文件保持不变。手动选择的风格仅是一组可修改参数。

## 真实控制与边界

- 磨皮：排除眼睛、眉毛、嘴唇的柔边区域降噪；最大混合比例已从0.66降至0.48。最大组合仍可损失纹理，不自动删除痣/雀斑，但无法保证它们不被弱化。不是 learned 祛痘。
- 提亮：有阴影/高光保护的线性光增益，不混入白色；0–100。自然预设为0。
- 冷暖：保持亮度的色彩微调。手机滑杆-40至40；共享核心兼容-100至100。
- 淡化眼下：依据下眼睑方向与相邻脸颊亮度，局部提升暗调；保护睑缘与眼球，不填平眼袋或声称消除眼袋。0–100。
- 匀红：相对本张照片的脸颊参考色，只减弱部分局部过量红色；不是所有肤色均匀化，不设目标肤色。0–100。
- 唇色：外唇内部柔边染色，扣除内口/牙齿，保留原亮度；自然、暖桃、柔玫瑰三色方向。高光/深色嘴部受保护。0–100。
- 气色：沿人脸方向的宽柔边脸颊区域染色；使用 OKLab 色度变化限制，避免滑杆最大值出现两个饱和粉色圆斑；保持原亮度。0–100。
- 祛痘：既有手动点涂，使用周围颜色平面修补，仍不是自动病灶识别或生成式修补；纹理质量有限。
- 塑形：既有局部几何变化，全部默认零，预设不触发；极端变化可能不自然，不是学习型重建。

新的眼下、匀红、唇色、气色必须有真实人脸关键点。未检测时禁用；切为手动圆圈会清零并停用它们。手动圆圈只保留磨皮、提亮、冷暖。导入不会自动美化。

## 参数与项目兼容

共享 API 保留五个函数。beauty(image, settings, landmarks) 新增 underEye、redness、lip、blush 数值参数，范围0–100，缺失均为0；palette 为 natural、peach、rose。单478/468关键点及最多5个网格可用；重叠区域逐通道取最大权重，只处理一次。

能力元数据在 PortraitEngine.beauty.capabilities。implementation 为 classical-face-color-v1，version 为1，learnedRetouch 为 false。桌面与手机共享核心；Android 不自动启用桌面后端的 learned matte 适配器。

手机操作列表中新增数值存入 beauty.values，palette 存于 beauty.palette。原有 v2 草稿可继续读取，新字段经严格范围验证。未支持新字段的旧版不应静默读取为不同效果。先从原始 Blob 重放整个操作列表，不把上一次预览作为下一次原图；撤销/重做保存原参数。

预设：自然通透 smooth16、underEye12、redness8；柔和妆感 smooth18、underEye12、redness8、lip18、blush12、palette peach。其余参数0，包括提亮与所有塑形。

## 已完成的质量证据

8张官方公开成人肖像，人物背景与成年证据来自 NASA/JAXA 官方资料，不从照片推断族裔。输入包独立保存，不打包为产品宣传素材。仅限私下信息性 QA，不代表人物背书。

在云端 CPU 使用 APK 同一份官方 Face Landmarker 模型推理，8张均得到478点。实际像素算法用约900×1000的保比例派生人脸裁剪，每张24组：零值、两个低强度预设、6个单控的25/50/100、上述六项组合25/50/100（冷暖与塑形0），共192组。不是7–39MP原尺寸或手机运行测试。

已逐项记录输入不变、零值完全一致、透明度保持、变化像素数量和最大差值。修正后192组没有新增255通道剪裁。最大气色单独控制的每通道变化为7–9个8bit值。原生全脸、下睑、嘴唇/牙齿、完整脸颊、额头到颈部对比均生成；检查中没有旧白色硬边面具或明显的两个粉色圆斑。

仍未通过：上述六项组合100的整体肤感过软，不能宣称所有强度或所有照片精修合格；没有真实痘痘、眼镜、强侧脸、强低照度等完整覆盖。新控制不是SOTA验收通过。看起来细微不等于没有处理，也不等于适合每个使用者。
