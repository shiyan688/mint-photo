# 我的配方：可复用调节与本机收藏

这是源码检查点，不是新的可安装 APK。当前 unsigned 编译通过，但没有新签名、真实 WebView 或手机验收。已有照片原始 Blob 与顺序编辑历史保留。

## 实际用法
1. 导入照片，进入「★ 我的配方」。调整曝光、对比、饱和、色温，或人像肤感/眼下/匀红/唇颊；色阶与曲线/HSL 在各自子面板编辑，返回时保留整套配方。
2. 人像非零参数必须先识别当前照片的人脸。没有定位时整套配方不生效，也不能应用；可明确点击「仅调色」，将全部人像参数归零，保留全局调色、色阶与曲线。
3. 命名后点「命名保存」。本机最多 40 条，名字需 1–48 个 Unicode 字符。加载已有条目后可改名或更新，覆盖需要确认；收藏、取消收藏与删除各自持久保存。删除不会改变照片历史。
4. 「导出当前配方」保存 .mintpreset.json 文件；Android 使用系统文件保存选择器，成功、取消、写入失败分别报告。浏览器仅报告已生成下载，不声称文件已写入设备相册。导入只替换待应用预览，不自动存入本机收藏。
5. 「应用」在当前历史末尾新增一步。再次应用会叠加，不会偷偷替换旧调节。想替换上次效果，请先撤销；「本次全部归零」只取消当前配方预览，照片全局撤销/重做仍可用。

## 可互通与不能互通
- 手机和桌面使用同一版本的严格 JSON 配方格式与调色核心；不是完整工程互换。
- 白名单只有 basic（曝光/对比/饱和/色温）、beauty（肤感与颜色参数）、levels（黑白点/中间调）和 advancedTone（曲线/HSL）。没有照片、文件路径、源图标识、时间、关键点、选区、手动笔划、裁剪或五官塑形。
- 旧手机版「亮度」历史仍用原来的数学含义，不会被改成共享的「曝光」。新配方明确采用 beauty → shared basic tone → levels → advanced tone，其他已有操作按手机顺序历史正常重放。
- 当前导出格式为 v2，色阶字段明确为 null 或严格配方。旧 v1 仅含原三组字段，加载时迁移为 levels:null，不会残留之前的新色阶；旧版本不认识 v2 时应拒绝，不承诺旧版直接读取新版文件。旧本机收藏只在内存读取时规范化，只有显式保存/更新才写回，收藏与ID不变。
- 目标照片的人脸定位仅保存在该照片的本机编辑历史内，导出配方时永不携带。定位不是学习型美颜；肤感处理仍是已披露的经典算法，最大组合依然可能过软。
- 离线 HTML 没有 Android 原生识别桥。可试用收藏、导入/导出和「仅调色」；不能据此声称浏览器已做人脸模型推理。

## 文件与并发保护
- UTF-8 64KiB 上限，拒绝重复 JSON 键（包括转义别名）、未知字段、错版本、异常值、过深结构、非法 UTF-8 或损坏数据；不会悄悄跳过字段或局部应用。
- 本机收藏总量上限 256KiB。存储写入成功后才更新内存；空间不足、读取损坏或另一页面已修改时不覆盖旧记录，可显式重读。清除应用数据仍会丢失本机收藏，重要配方请导出备份。
- 正在系统保存照片时不能另存配方，反过来也相同；图片和配方使用不同完成回调，保存 JSON 不会把照片标为已保存。
- 换配方、归零、选择仅调色或退出工具后，迟到的导入/人脸识别结果不能恢复已放弃的状态。重复识别会取消前一个等待状态，只接收最新请求。

## 验证边界
- 严格格式、持久存储失败、生产 UI 状态、完整 editor 历史/撤销与并发回调均有自动回归。
- 独立内存 Skia Canvas 运行真实像素顺序：配方 → 液化/克隆 → 裁剪/旋转/翻转，并核对重复重放、源图 Blob 与 PNG 字节不变。它不是 Android WebView。
- 一张公开 NASA 派生肖像（897×1000、478 个真实定位点）上，历史 v1 手机配方核心输出与桌面逐字节相同，证据见 PRESET-PUBLIC-PIXEL-PARITY.json。同一肖像上的第二条配方同时启用肤感、基础调色及曲线/HSL，也与桌面逐字节一致。
- 新 v2 的人像、基调、色阶、曲线四组同时活跃时，实际手机适配器和完整编辑器原尺寸 PNG 解码也与桌面逐字节相同，见 LEVELS-PRESET-PUBLIC-PARITY.json；不借用历史 v1 结果冒充 v2 验证。
- 不含新美颜模型，不是 SOTA 验收，不代表所有肤况、设备存储提供方或系统文件选择器已验证。完整计数与 unsigned 编译结果见 CLOUD-VALIDATION-2026-10-22.json。
