# 原文件保留与明确分辨率导出

此功能属于当前重做源码，不代表新的签名 APK 或真机验收。

## 数据流

- 导入后的权威来源是原始 File/Blob。缩小画布只用于工作和预览，不再重新编码后替代原文件。
- 记录解码器实际返回的方向修正尺寸，不把文件头宽高与显示方向混用。EXIF 方向的真实 WebView 差异仍待设备测试。
- 草稿 v2 原子保存来源、已应用操作和重做历史。Blob 原字节保持不变，操作及蒙版验证后复制。
- v1 草稿迁移为 legacy-working-copy。旧工作副本只能恢复已保存的像素，不能恢复以前导入时丢掉的高分辨率。
- 未应用预览不加入项目；每步裁剪、关键点、绘画和蒙版沿用其输入坐标系中的归一化规则，按原顺序重放。

## 明确的资源预算

- 导入文件不超过 40 MiB、解码后不超过 8000 万像素。浏览器 Image 在尺寸检查前可能已经分配解码内存，这不是大型照片不会内存失败的保证。
- 原尺寸导出在解码前检查输入与每个中间阶段：最多 8,000,000 像素，最长边 4096。这个保守预算尚未经实际手机内存、发热与速度验收。
- 不满足原尺寸预算时明确显示不可用原因，保留原文件，保存按钮保持禁用，用户必须明确选择「工作尺寸」后才能继续，并在保存前看到实际输出尺寸。不会自动默认缩小或在原尺寸模式中偷偷缩小。
- 工作尺寸从最长边 2560 的工作副本重放。ID-photo 是明确固定尺寸阶段，仍输出用户所选像素规格；它不是按缩放系数放大的高分辨率照片。
- 原尺寸重放不会把原有 256px 人像置信度蒙版变成发丝级 matting，也不意味着经典修肤算法达到 SOTA。
- 编码后再次检查格式与 48 MiB 原生传输上限，再交给原有系统保存流程。不增加原生载荷限制或网络权限。

## 失败与并发

- 新图片或草稿验证、解码、预览成功后才完成替换；失败回滚已打开项目。
- 导入、示例准备、恢复使用代次校验；过期结果不会覆盖后来选择的照片。
- 导出捕获源、编辑列表和修订号。生成期间变更会取消该次导出；系统保存窗口回来后，旧版本保存成功也不会把后来编辑标为已保存。
- 新增操作先验证，再渲染；失败恢复已有操作与预览。原文件始终不变。
- 已保存的原文件可能包含原始 EXIF/定位元数据，但仅留在本机草稿。导出重新编码为新 JPG/PNG，不主动复制原始元数据。
- IndexedDB 容量不足会明确提示，不声称草稿已保存。不包含云备份、跨设备工程或无限历史。
