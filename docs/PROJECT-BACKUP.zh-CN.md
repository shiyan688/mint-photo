# 工程文件备份与恢复

当前是云端验证的未签名源码检查点 v27。不是已安装 Android App 的验收报告，旧签名安装包没有更新。

## 使用

1. 在「作品库」中填写名称，选择「导出工程备份」。先阅读完整原照片提示，再通过系统保存窗口选择位置。
2. 在「作品库」选择「从工程备份恢复」，只选择一份 `.mintproject` 文件。当前已应用作品、原图、重做步骤与内嵌图片会恢复为新的当前草稿。
3. 如当前作品未保存，会先确认并保留可恢复的旧草稿。恢复后仍需命名保存到本机作品库；备份文件本身不改变。
4. 备份不包含尚未点击「应用」的预览，但导出不会丢弃该预览。导出成功也不会把当前作品误标为已经命名保存。
5. 校验/传输期间可以取消。系统保存窗口出现后，用系统的取消按钮。只有系统文件写入完成回调才报告保存成功；浏览器预览只能报告已发起下载，不能证明文件落盘。

## 隐私与文件边界

- **备份未加密**，包含完整主原文件、已应用与重做历史、内嵌工作素材，以及人像步骤中已有的人脸坐标。照片元数据也随主原文件保留。它不是只含参数的 `.mintpreset.json`，也不是导出的脱敏照片。
- 即使画面已经涂黑或遮盖，备份中的原照片仍可恢复。不要将工程备份当作已脱敏图片分享，也不要将 SHA-256 校验当作加密、签名或可信来源证明。
- App 不上传照片、不使用网络。保存目的地由用户在系统选择器中决定；“仅本地”请求只是提示，第三方或云文件提供商仍可能自行同步。
- 总文件最多 64 MiB，JSON 清单最多 24 MiB，主原文件最多 40 MiB。最多 60 步；主原文件尺寸最多 80 MP。已有贴图/拼图历史仍合计最多 4 张外部工作素材、16 MiB RGBA；每张的既有尺寸限制不变。
- 本版仅接受静态 PNG、JPEG、WebP 原文件；不支持 APNG、动画 WebP、HEIC 或 GIF 工程备份。设备是否能解码仍须检查。原始尺寸完整保留，不表示所有效果能在原始尺寸预算内导出。
- 这是固定头部＋UTF-8 清单＋原文件字节的单一二进制格式，不是 ZIP，不接受目录、路径、脚本或外部 URL。没有照片网络取回或外部素材引用。
- Android 手机工程保留其有序历史，**不与桌面工程互换**。旧 v1 工程只能恢复其已有工作副本，不会凭空找回旧版没有保存的原照片。

## 数据保护

先检查总长、版本、严格 UTF-8/JSON、重复键、数值边界、清单与原文件哈希、源格式头与尺寸；再实际解码、核对方向尺寸、预演当前及可重做历史后才提交替换。可编辑文字、绘画与贴图的旧版本也在相应历史边界预演，不能仅凭最终删除状态掩盖旧错误。历史预演使用工作预览预算，不是完整原尺寸或所有设备内存可用性的证明。

损坏文件、解码错误、不可运行的重做、取消和存储失败均保持当前作品。事务写入失败回滚。可用性不依赖本机数据库：数据库满时仍能尝试导出文件救回当前工作，但必须确认系统真的保存成功再退出。

原生出口逐块写入私有临时文件，校验完整后才打开系统保存窗口。取消/失败清理应用拥有的临时文件；崩溃后的陈旧缓存由后续启动清理。外部提供商在 I/O 失败时可能留下不完整文件，清理是尽力而为。系统正在写入时进程重建会提示结果未确认，不自动重复写入或宣称成功。新页面没有旧请求时仍显示“此前工程备份”的通知，但不会将当前作品标为已保存或改变新请求。

## 已做与未做

- 实际生产编辑器 + 原生 Canvas：调色、透明贴图、旋转、锐化及重做的备份/恢复/原尺寸 PNG，原文件与 RGBA 逐字节一致；另测两个已核 478 点坐标夹具及资产恢复，这不是对合成测试图重新识别到人脸的声明。
- 独立严格格式/哈希/UTF-8/数字语料、Java 与 JS 边界对照、分块乱序/取消/迟到结果、真实绘图与故障注入存储验证。
- 数据库和文件选择器在测试中是受控替身；不是浏览器 IndexedDB、Android SAF 或真机持久化结论。损坏压缩数据的解码容错因实现而异，不把本机解码器能输出图像当作严格压缩格式认证。
- 未跑实体设备：权限/提供商差异、断电/进程死亡、低内存/低存储、后台恢复与实际速度仍待验收。未生成新签名密钥。
