# v29 本地照片背景

## 操作与保存

进入「背景」，先自动生成已有模型的连续置信度或手动勾画，再选择「照片 / 选择本地背景」。只能导入 PNG、JPEG 或 WebP。选择本地图片、替换失败、取消、返回或迟到的读取结果不会替换当前主照片；失败会保留此前草稿背景。

- 「铺满」等比例覆盖画布，必要时只裁掉背景的边缘；「完整显示」不裁背景，剩余区域按透明或指定颜色铺底。横向/纵向对齐0是左/上，50是居中，100是右/下。
- 背景的铺放永远不改变前景的尺寸、位置或画布尺寸。使用已有缩放/平移检查边缘；第二触点取消尚未完成的修边笔划。
- 选透明时，背景素材透明处和完整显示的空白可保持透明。指定铺底色或最终 JPEG 导出可能将这些区域铺为不透明。前景覆盖率为原图 alpha × 连续蒙版；并非强制整个输出 alpha 与原图相同。
- 应用后成为可撤销的有序步骤。后续裁剪/转向等仍按既有历史顺序执行，不回写前面步骤。主原文件不改动；新增背景只是该步骤的独立工作资产，不是新的主原图。
- 保存到本地作品库、另存副本和 `.mintproject` 备份都包含此工作资产、蒙版与笔划；不依赖原背景文件路径、网络地址或临时 URI。此备份未加密，包含主原照片和照片内容；提供商可能同步用户选择的备份目标。

## 分辨率与预算

背景文件最大12 MiB，解码图像最大8,000,000像素、边长4096，再按现有本地贴图导入器归一化到长边不超过1024、最多1,048,576像素。界面显示选择时解码尺寸和实际工作尺寸。**不保留第二张照片的完整原文件，放大背景不会增加细节。** 这是有界素材方案，不宣称高清背景原文件保真。

背景素材与贴图、拼图共用每份历史最多4张、16 MiB原始RGBA的额度，含保存的重做记录。原尺寸处理的当前步骤输入上限8,000,000像素/4096边；最终导出缩小不能绕过中间画面的预算。

照片核心的额外缓冲计划最多64 MiB、工作100M单位；加上连续蒙版与Canvas中间缓冲，适配器先检查256 MiB额外缓冲和512M累计重放工作预算。这些不是Android进程总峰值或低端机流畅保证。同步计算支持合作式检查，但并不意味着UI线程随时能中断。

## 算法与边界

连续蒙版先按实际输出尺寸重放。背景采用有界面积预滤波，再在预乘线性光RGBA中重采样，避免透明RGB泄漏和明显缩小棋盘混叠；以连续覆盖率合成，绝不把置信度阈值化成二值剪影。完全保留的不透明前景像素保持逐字节不变。Canvas或PNG对完全透明像素的隐藏RGB仍可能规范化。

本轮没有更换既有 MediaPipe 分割模型。公开肖像对照沿用已存档的云端CPU置信度与人工修边配方，不是新的Android推理或发丝分割证明。头发、肩部灰边、旧背景污染和透明物体仍可能不自然；本工具没有前景颜色去污染、补发丝、光照重建或SOTA效果承诺。

## 验证与未验证

纯数学、实际生产编辑器的NativeCanvas/PNG、原文件哈希、撤销/重做、几何顺序、文件解码、共同素材额度与备份到新会话回放均有测试。DOM、文件选择器、native bridge和IndexedDB后端为受控/注入测试，不是真实浏览器事务或手机操作。

正常安全设置下云端浏览器运行仍受限制，未以关闭沙箱绕过。当前SDK没有可用emulator程序，也没有完成新签名授权；本轮只做两ABI未签名编译，不修改已交付APK。Android WebView布局、真实SAF、持久化、系统回收、触屏与设备内存/速度仍待实测。

源包保留测试、生成器、蒙版/配方与小对照。完整PNG另存「安卓照片背景-v29-质量证据.zip」，避免源包持续膨胀。核心API与资源公式见 `PHOTO-BACKGROUND-CORE.md`；独立结果见 `quality/photo-background-independent/AUDIT.md`。
