# 最终导出尺寸

这是云端源码检查点，不是已签名安装包或 Android WebView / 真机验收。

## 使用

1. 打开“导出”，先确认重放来源：保留的原图，或明确选择最长边 2560 的工作副本。
2. 最终尺寸默认“不缩放处理结果”。可以选择长边 1080、1440、2048，或输入自定义的 1–4096 整数像素。
3. 保持当前处理结果的宽高比例，短边四舍五入、至少 1 像素。保存前会显示最终宽 × 高，同时显示缩放前的处理尺寸。
4. 只缩小、不放大。目标长边大于当前处理结果时明确报错并禁用保存，不悄悄把输入改小或插值凑分辨率。重新打开导出面板时回到“不缩放”，JPG 画质选择保留。

## 顺序与安全

- 先按历史顺序从原图或工作副本重放全部操作，裁剪、旋转、翻转和留白均已完成，最后才缩小。
- 最终导出尺寸不是编辑操作，不改变原始 Blob、任何人脸/画笔坐标、撤销/重做或本地草稿。
- 1 像素的小输出也不能绕过源图与每个中间阶段的 800 万像素 / 最长边 4096 预算。不满足原尺寸预算时仍须明确选择工作副本，不能把它称作原图重放。
- 最末缩放的两张 RGBA8 画布按输入+输出估算，合计不超过 64 MiB；相同尺寸不额外分配输出。这不等于整个应用只用 64 MiB，未计其他工作画布、历史、编码器、浏览器/GPU 内存。
- 保存开始时捕获尺寸、来源、格式和画质。后续控件变化不能改变正在生成的文件；项目变化、分配/编码失败和取消仍保留原图与历史。
- PNG 保留透明信息，缩放会重新计算边缘的半透明像素。JPG 在缩放后用白底合成透明区域，再按选择的画质编码；输出重新编码，不携带原始定位信息。此轮未增加原生权限或传输上限。

## 验证与限制

- 纯规划核心做了严格字段/数据属性校验，确定性尺寸回归、边界和预算检查。
- 完整生产编辑器在云端 Native Canvas 上验证了实际 PNG/JPEG、透明像素、白底、质量、裁剪/旋转/翻转/非对称留白组合和失败保留。
- `quality/export-size-evidence/comparison-zh.png` 是自制图的实际导出像素，不是浏览器界面或手机截图。
- 使用浏览器原生高质量 Canvas 重采样；不是 AI 超分，也不承诺不同系统逐像素相同。小图仍会损失细节。
- 真实 WebView 的重采样、EXIF/色彩管理、系统保存器、手机内存/温度与操作体验仍待设备验证。
