# 边框 / 画布留白

这是本地、可撤销的真实画布扩展，不是生成式扩图。不会补画照片内容，也不会缩小照片来挤出边框。

## 使用和尺寸

- 打开「边框/留白」时默认为零留白，不改变照片。可选均匀白边、底部加宽、透明留白，也可分别调整四边、颜色与不透明度。
- 四边各为当前编辑阶段照片短边的 0%–50%。每边独立计算 round(短边 × 比例)，取整为像素；输出宽度 = 输入宽度 + 左边 + 右边，高度同理。
- 面板区分「原尺寸布局」的数学尺寸与实际可导出的原尺寸/工作尺寸。计算一个大图的布局尺寸不代表已解码、分配或可安全导出它。
- 原尺寸与工作尺寸都会用实际操作序列检查预算。超过 800 万像素或 4096 边长的任何阶段会拒绝导出，不会偷偷缩小冒充原尺寸。如果两种导出方式都不安全，新的留白设置不予接受。
- 最高可保留 8000 万像素的原文件仍可能允许工作尺寸导出；不会仅因为原尺寸布局超过共享像素核心的 64 Mi 像素上限，就错误拒绝安全的工作尺寸方案。
- 预览与导出分别取整，边框可能有不足一个像素的相对取整差异。导出前会展示最终像素尺寸，而不是把预览放大。

## 原图与透明度

纯 RGBA 核心将输入图像逐字节搬到新增左边、上边对应的偏移位置，不插值、不缩放，保留输入的 RGB、alpha 和透明像素下的隐藏 RGB。完全透明的新边框统一填充 RGBA(0,0,0,0)，不会复制照片中的隐含数据到边框。

这项逐字节保证指传给纯核心的当前栅格。浏览器 Canvas 本身存在预乘 alpha、解码和编码行为，不能由此承诺原始 PNG 文件的隐藏 RGB 经过 Canvas 后仍然逐字节一致。原始导入 Blob 独立保留，没有被边框替换或重编码。

PNG 可保留新增透明留白和原图透明度。JPEG 不支持透明，本应用明确将整个导出结果合成到白底；半透明彩色边框因此会与白色混合。照片导出本身仍重新编码。

## 历史和坐标

边框是手机工程中的一个有序步骤。之前的裁剪、旋转、调色、手工笔划、文字先重放，然后扩展画布；之后的操作基于扩展后的画面坐标。提交后会更新照片版本并作废旧的人脸/背景检测缓存，不能把旧照片坐标直接套到新留白画面。

「重置为零留白」只重置尚未应用的当前预览，不会暗中删掉历史里已应用的边框。已应用的步骤可用主工具栏撤销/重做；原照片与原始历史仍保留。没有任意位置重新编辑旧边框的图层功能。

无效配方、尺寸超限或画布分配/显示失败不应修改原照片及已有历史。同步像素循环不承诺在手机上即时响应中途取消；实际触控、内存和性能仍需真机验收。

## 云端测试边界

共享核心的独立像素参考、透明度、零值、严格字段和预分配取消测试使用普通 Node。额外原生 Skia Canvas 测试用于真实 PNG 和生产编辑器重放，不等于 Chromium、Android WebView、系统文件选择器或手机实测。示例图使用自建合成底图，没有私照、第三方素材库、模型下载、上传照片或新签名。
